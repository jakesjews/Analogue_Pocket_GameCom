## Version 0.2.0

- Review fixes: cartridge-ROM prefetch, Memories requests during reset, the 13th touch column, waking the Game.com from STOP with the Pocket buttons, a running RTC, grayscale display-mode support, clock-crossing hardening and mailbox skew constraints. See [port architecture](PORT.md).
- ROM latency, measured before the change with a standalone `pocket_rom` testbench at nominal clocks: every cache miss took exactly seven 20 MHz clocks (350 ns), against a 200 ns CPU bus cycle, and the one-halfword cache missed on every other byte of straight-line code.
- `rom_tb`: passed. Adds 3000 random-address reads with random gaps and two sequential streams at and above CPU bus speed, all checked against the loaded pattern. With prefetch, 600 sequential reads at CPU bus speed waited 15 clocks in total; the previous design would have waited about 7 clocks on every other read.
- `state_tb`: passed. A capture and a restore requested while the machine is in reset are both acknowledged with an error and never pause the machine; a blob written during reset restores afterwards. The previous `pocket_state` times out on the first of these checks.
- `setup_tb`: passed, through the real `core_top` and `core_bridge_cmd`. Memories commands `00A0`/`00A4` sent while the host holds reset return result 3 instead of stalling the command handler. Command `00B8` with the grayscale bit returns `444D` in the response word and selects the gray palette; a color mode releases it.
- `io_tb`: passed. The cursor reaches column 12 (the thirteenth), the right stick moves it through the new thresholded path, and a face button produces a Power press only while the Game.com is stopped.
- `rtc_tb`: passed. Seeding from the host value, second-to-year carries, 29 February in a leap year, 28 February otherwise, and 2099 to 2000.
- `bios_tb`, `dma_tb` (13 cases) and `video_cadence_tb`: passed unchanged.
- `setup_tb` also checks that the menu's Game.com Power action reaches the key matrix through the reworked clock crossing.
- Wake from STOP could not be exercised in the full system. With this BIOS and blank console memory, the BIOS never executed STOP within 3 emulated seconds: not at boot without the automatic Power press (it played the Tiger intro), and not at the organizer menu with Power held for 0.1, 0.6 or 2 seconds. The wake path is therefore covered by `io_tb` (the Pocket side) plus the existing upstream STOP-wake logic that the menu Power action already uses; a physical check remains pending.
- Cartridge speed, full system (`boot_tb` with the real Pocket wrapper, SRAM and PSRAM pin models, and the MAME-set external BIOS with blank console memory). Each game was launched from the organizer menu and checkpointed at its copyright screen. Both designs then resumed the same checkpoint, pressed A and ran 3 emulated seconds. Share of non-halted CPU cycles spent waiting for cartridge ROM:

  | Game | 0.1.4 | 0.2.0 | Cartridge accesses completed |
  | --- | ---: | ---: | ---: |
  | Sonic Jam | 5.50% | 1.66% | +2.2% |
  | Lights Out | 15.70% | 4.56% | +4.7% |
  | Resident Evil 2 | 13.49% | 2.83% | +16.7% |

  ROM wait cycles fell by 70–79%. All frames passed the geometry checks and the captured images are clean; in the same 3 seconds 0.2.0 Lights Out reached its START/EXIT title menu while 0.1.4 was still in the grid animation. The CPU halts for under 7% of cycles in these scenes, so the waits were a direct slowdown. The remaining misses are jumps and table reads outside the two prefetched halfwords. Physical motion retesting on a Pocket is pending.
- Live Memories in the full system with the final RTL: during Lights Out, a capture and a restore through the APF bridge restored PC `5e68`, both 8 KB VRAM banks and the 8 KB console RAM, and the game continued with all frame checks passing. The bench now compares machine state when the restore finishes, while the machine is still paused. It used to compare when APF's `ok` arrived, which only worked because the old two-flop status path happened to deliver `ok` within the single 50 ns cycle before the machine resumes; the stable-sample status path takes a few bridge clocks longer.
- Quartus 18.1 build of 0.2.0: successful. The first fit failed one fast-corner (1100 mV, 0 °C) hold check by 9 ps, on a CPU GP-store port-A write-data path into M10K; the packager refused it. The existing 250 ps GP-store hold reservation now covers both RAM ports, and no bound was relaxed. Final fit: 16,645 ALMs (90%), 5,922 registers, 119 M10Ks, 911,360 RAM bits. All 80 constrained timing groups pass: minimum setup 0.475 ns, hold 0.056 ns, recovery 29.776 ns, removal 0.282 ns, pulse width 0.833 ns. Evidence of the first fit: `build/v0.2.0-first-fit/`.
- Mailbox net-delay bounds: all four are analyzed and pass (request address 2.235 ns of 5 ns, audio sample 1.463 ns of 5 ns, ROM data 2.600 ns of 20 ns, boot date/time 2.164 ns of 20 ns). An earlier `set_max_skew` formulation matched the registers but Quartus 18.1 reported no paths through the asynchronous clock groups and ignored it, so it was replaced. Evidence: `build/net-delay.rpt`.
